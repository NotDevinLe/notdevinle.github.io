`REAP` is a paper on ways to prune experts. The reason this is so good is because for many SMOE models, they make up a majority of the parameters. By reducing the number of experts we store, we can save a lot of memory at the cost of a little performance.

Before diving too deep into the pruning, it's important to understand the model itself. First, we will embed each token. Afterwards, they get passed into a transformer block. Once one transformer block finishes being processed, it is then passed into the next and so on.

## Methodology

`REAP` follows three steps:
    1. Run callibration over a dataset that is representive of the usecase
    2. Prune the model based on experts with the least score
    3. Save model and reuse

We can calculate the score of each expert by using the following formula:

![reap formula](/images/reap_formula.png)

That might look a bit intimidating but it's not bad at all. Let j be the expert id. We also let `X_j` be the tokens where expert j was selected. `pi_j` is the router probability for expert j under the token x. `||f_j(x)||` is simply the magnitude of the output vector of the expert under token x.

How you can think about it is that expert j contributes the inner of the summation amount for some output. If you find the average of it, then this expert will usually contribute that much. You want to remove experts that usually don't contribute much.

## Issues with running on TPUs

so the original codebase was written for pytorch on cuda. On gpus, we hook onto each MOE layers and have an observer get the scores. However, on tpus, we use a JIT compiler which means that that the compiler will compile the code in an efficient manner and all of the MOE layers will be treated as one for reducing redundancy. Therefore, a callback doesn't know which layer it comes from.

`Attempt`: Keep an incremental counter during trace time so that the compiler will recognize each layer as a different code. However, what actually happens is that the compiler freezes the counter at one value and treats the layers as the same still.

`Solution`: We introduce another parameter that is instead an array where each layer index is corresponding to the array index. This passes in the layer as a parameter instead of a value in the compiler's eyes which makes 42 separate layer compilations.
